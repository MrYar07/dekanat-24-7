# «Деканат 24/7» — правила для ИИ-агентов

Прототип личного кабинета студента вымышленного университета «Меридиан» для конкурса MGIMO AI Challenge 2026 (номинация «Вайб-кодинг»). Код пишут ИИ-ассистенты, автор ставит задачи и проверяет результат.

Перед работой прочитай:
- [docs/PRD.md](docs/PRD.md) — что строим и зачем, приоритеты P0/P1/P2;
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — стек, модель данных, правила безопасности;
- [docs/GRADING.md](docs/GRADING.md) — правила оценивания и рейтинга «Меридиана». Расчёты делаем строго по нему, числа берём из настроек, а не пишем в код.

## Жёсткие правила (нарушение = работа не засчитывается)

1. **Только вымышленные данные.** Никаких реальных ФИО, оценок, зачёток, логинов. Никаких подключений к системам реальных вузов.
2. **Никаких логотипов и названий реальных вузов в интерфейсе.** На каждой странице видна плашка «Концепт для конкурса MGIMO AI Challenge. Не официальный сервис. Все данные вымышлены».
3. **Студент видит только свои данные.** Любой запрос к базе фильтруется по пользователю из сессии. ID из URL или тела запроса не доверяем. Чужой объект → 404.
4. **Роли проверяются на сервере**, не скрытием кнопок.
5. **Пароли только argon2id.** Секреты только в переменных окружения сервера, никогда в коде, в `NEXT_PUBLIC_*` и в браузере.
6. **Сторонние материалы только с открытой лицензией.** Новую зависимость, шрифт или иконку записывай в раздел лицензий README.

## Интерфейс

- Язык интерфейса — русский, тон дружелюбный, на «ты».
- Mobile-first: всё работает от 360 px. На телефоне навигация — нижняя панель вкладок.
- У каждого экрана есть состояния загрузки, пустое и ошибки. Пустое состояние подсказывает, что делать дальше.
- Доступность: контраст WCAG AA, фокус виден, у иконок-кнопок есть `aria-label`.
- Дизайн-система «Зачётка»: цвета только из токенов `globals.css`, готовые компоненты из `src/components/ui` (витрина — `/design-lab` в режиме разработки). PT Serif (`font-serif`) — заголовки и цифры, Golos Text — всё остальное. Красный — только ошибки и переносы; «готово» — фиолетовая печать `Stamp`; статус всегда словом и иконкой, не только цветом.

## Как работаем

- Маленькие шаги: одна функция → проверка → коммит.
- Готово = работает на 360 px и на десктопе, есть тест на ключевую логику, проверка доступа для новых данных, без ошибок в консоли.
- Новый маршрут с данными пользователя → добавь Playwright-тест «чужой ID возвращает 404».
- После заметного этапа добавь запись в [docs/process/JOURNAL.md](docs/process/JOURNAL.md): что сделали, ключевой промпт, что пошло не так и как исправили, скриншот. Из журнала собирается отчёт для жюри.

## Структура

- `src/app/(student)/` — кабинет студента, `src/app/staff/` — кабинет сотрудника, `src/app/login/` — вход.
- `src/lib/auth/` — пароли, сессии, слой доступа (`dal.ts`: `requireUser`, `requireRole`).
- `src/components/ui/` — компоненты дизайн-системы: кнопки, поля, статусы и печать, ведомость, пометки, пустое состояние, ошибка и заглушки загрузки.
- `src/lib/data/` — запросы к данным. Функции для студента **не принимают id**: студент берётся из сессии.
- `src/lib/grading/` — расчёт по GRADING.md, тесты рядом.
- `src/db/schema.ts` — схема Drizzle, `drizzle/` — миграции, `scripts/seed.ts` — вымышленные данные.

## Команды

```bash
npm run db:start      # локальный PostgreSQL (держать запущенным)
npm run db:generate   # миграция из изменений schema.ts
npm run db:migrate    # применить миграции
npm run db:seed       # пересоздать вымышленные данные
npm run dev           # http://localhost:3000
npm test              # юнит-тесты
npm run test:e2e      # Playwright: доступ к чужим данным, сценарии жюри (нужны база, сид и Chrome)
npm run typecheck && npm run lint && npm run build
```

Пароль тестовых аккаунтов в разработке — `SEED_PASSWORD` в `.env` (файл не коммитится, шаблон — `.env.example`).
