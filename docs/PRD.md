## 1. Одной фразой

**Ни одного лишнего похода в деканат и ни одной оценки, о которой узнаёшь в конце триместра.**

## 2. Проблема

Учебная жизнь студента разбросана: расписание на сайте, оценки в отдельной системе, справки через очередь, объявления в чатах. С телефона найти нужное трудно.

Две боли подтверждены личным опытом автора (студент МГИМО). Их нужно проверить опросом однокурсников, см. [research/survey.md](research/survey.md).

### Боль 1. Справка = 3 похода и 2 дня

1. Студент лично идёт в деканат и просит справку.
2. На следующий день приходит забирать.
3. Идёт в другой кабинет ставить печать.

**Метрика «до → после»:** 3 визита и ~2 дня → 0 визитов и ~1 минута (типовая справка) или 1 визит (бумага с печатью).

### Боль 2. Оценки видны только в конце триместра

На сайте с оценками они появляются поздно, к концу триместра. Нельзя посмотреть динамику и формирующийся средний балл в реальном времени. Студент узнаёт, что «всё плохо», когда исправить уже поздно.

**Метрика «до → после»:** оценка видна через недели → через секунды после выставления.

## 3. Пользователи и роли

| Роль | Кто | Что делает в системе |
|---|---|---|
| Студент | главный пользователь, чаще всего с телефона | смотрит день, расписание, оценки; заказывает справки; читает уведомления |
| Преподаватель | ставит оценки | журнал своих групп, выставление текущих и экзаменационных оценок |
| Сотрудник деканата | обрабатывает заявки | очередь заявок, смена статусов, объявления, переносы пар |
| Гость | любой, кто получил справку | проверяет подлинность справки по QR-коду, без входа |

## 4. Ключевые сценарии (их проходит жюри)

1. **Утро студента.** Вход → экран «Сегодня»: следующая пара с аудиторией, перенос выделен, новая оценка, справка готова.
2. **Справка за минуту.** «Справки» → «Справка с места учёбы» → цель и количество → PDF готов сразу, с QR-кодом. Скачать или поделиться.
3. **Справка с печатью.** Заявка → статус «подано» → сотрудник деканата меняет на «готово, каб. 214» → у студента уведомление.
4. **Живые оценки.** Преподаватель ставит оценку → у студента появляется уведомление, пересчитывается средний балл, сдвигается график.
5. **«Что нужно, чтобы…».** Студент выбирает предмет и цель («закрыть на 5») → калькулятор показывает, какую оценку нужно получить на экзамене.
6. **Разделение данных.** Студент А подставляет в адрес ID заявки студента Б → получает «не найдено».
7. **Проверка справки.** Гость сканирует QR → публичная страница: тип документа, дата выдачи, «действительна», ФИО в маскированном виде.

## 5. Функции

Приоритеты: **P0** — обязательное ядро задания, без него работа неполная. **P1** — наши фишки, ради них работу запомнят. **P2** — если останется время.

### 5.1. Вход и профиль — P0
- Вход по логину и паролю. Ограничение числа попыток, понятные ошибки.
- Профиль: ФИО, фото-аватар (сгенерированный), факультет, направление, курс, группа, номер зачётки (вымышленный).
- Выход со всех устройств.
- На экране входа подсказка с тестовыми аккаунтами для жюри.

### 5.2. Экран «Сегодня» — P0
Главный экран вместо меню. Карточки по важности:
- текущая или следующая пара (время, аудитория, преподаватель, сколько до начала);
- переносы и отмены на сегодня и завтра (выделены цветом);
- новые оценки с момента прошлого входа;
- заявки, у которых изменился статус;
- ближайшие дедлайны;
- непрочитанные объявления.

Пустые состояния продуманы: «Сегодня пар нет — отдыхай», «Новых оценок пока нет».

### 5.3. Расписание — P0
- Вкладки «Сегодня» и «Неделя», листание недель.
- Пара: время, дисциплина, тип (лекция, семинар), аудитория, преподаватель.
- Переносы и отмены: старое время зачёркнуто, новое выделено, есть причина.
- P2: экспорт в календарь (.ics).

### 5.4. Успеваемость «Как у меня дела» — P0 + P1
- **P0:** список дисциплин текущего триместра с оценками и итогами; зачёты и экзамены сессии; архив прошлых триместров.
- **P0:** сводка «как у меня дела»: средний балл, долги, светофор по предметам (зелёный, жёлтый, красный).
- **P1:** оценки появляются сразу после выставления преподавателем.
- **P1:** график динамики по предмету и по среднему баллу за триместр.
- **P1:** формирующийся средний балл и прогноз итоговой оценки по предмету.
- **P1:** калькулятор «что нужно, чтобы…»: какая оценка на экзамене даст нужный итог.
- **P2:** «риск потерять стипендию» с подсказкой, по каким предметам подтянуться.

### 5.5. Справки и заявления — P0 + P1
- **P0:** каталог документов: справки (с места учёбы, для военкомата, для стипендии, для визы), заявления (академический отпуск, перезачёт, пересдача — с формой).
- **P0:** «Мои заявки»: список и статус-трекер «подано → в работе → готово → выдано / отклонено» с датами и комментарием сотрудника.
- **P1:** типовые справки формируются сразу: PDF с QR-кодом проверки подлинности. Печать не нужна.
- **P1:** если нужна бумага с печатью: статус «готово, забрать в каб. N, печать уже стоит».
- **P1:** публичная страница проверки справки по QR (без входа, минимум персональных данных).

### 5.6. Уведомления — P0
- Лента: новые оценки, статусы заявок, переносы, объявления деканата, напоминания о дедлайнах.
- Счётчик непрочитанных, «отметить всё прочитанным», фильтр по типу.
- Обновление без перезагрузки страницы.
- P2: push-уведомления (PWA), рассылка в Telegram.

### 5.7. Кабинет сотрудника — P1
Минимально, 2–3 экрана на роль:
- **Преподаватель:** мои группы → журнал группы → поставить оценку в одно касание.
- **Деканат:** очередь заявок с фильтром по статусу → карточка заявки → сменить статус, добавить комментарий. Публикация объявления для курса или группы. Перенос пары.

### 5.8. ИИ «Спроси деканат» — P1
Строка вверху любого экрана. Понимает свободный текст и ведёт к действию, а не просто отвечает:
- «нужна справка в военкомат» → открывает заполненную форму заявки;
- «какой у меня средний?» → карточка со средним баллом;
- «где завтра первая пара?» → карточка пары.

Правила:
- работает **только** с данными вошедшего студента, на сервере;
- ключ ИИ-провайдера хранится только на сервере;
- если ИИ недоступен или не уверен, строка работает как обычный поиск по разделам, ничего не ломается.

## 6. Нефункциональные требования

| Требование | Как проверяем |
|---|---|
| Работает на телефоне от 360 px, все сценарии | Playwright-тесты в мобильном viewport, ручная проверка на реальном телефоне |
| Студент видит только свои данные | тесты на подмену ID в адресах и API |
| Пароли не хранятся в открытом виде | argon2id, проверка в коде и в базе |
| Ключи не лежат в коде и в браузере | секреты только в переменных окружения сервера, `.env` в `.gitignore`, проверка сборки клиента |
| Только вымышленные данные | генератор seed-данных, ручная проверка |
| Открывается из России без VPN до 28.11 | российский хостинг, проверка с мобильного интернета |
| Быстро | первая загрузка < 2 с на 4G, Lighthouse ≥ 90 (mobile) |
| Доступно | контраст WCAG AA, работа с клавиатуры, подписи для экранных читалок |
| Масштабируется | stateless-приложение + PostgreSQL, можно поднять несколько экземпляров |

## 12. Открытые вопросы

1. **Система оценивания.** Пока предполагаем: текущие оценки по 5-балльной шкале с весами (семинар ×1, контрольная ×2), итог по дисциплине — средневзвешенное с экзаменом. Уточнить, как это устроено в реальности, чтобы адаптация была правдоподобной.
2. **Хостинг.** Нужен аккаунт у российского облачного провайдера (Timeweb Cloud, Selectel или Yandex Cloud) и, желательно, домен. Решает автор.
3. **ИИ-провайдер для «Спроси деканат».** YandexGPT или GigaChat: нужен API-ключ.
4. **Результаты опроса** могут добавить третью боль и поменять приоритеты P1.
